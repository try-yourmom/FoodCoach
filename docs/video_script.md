# 运行视频脚本

## 录制前准备

- 启用 API Key，并先用一张图片确认两种方案都能成功返回
- 终端执行 `.\scripts\run_all.ps1`
- 浏览器打开 `http://127.0.0.1:8501`
- 准备 2～3 张学校餐盘照片；其中至少一张固定用于双方对照
- 放大浏览器到 125%，关闭无关通知

## 推荐时长

5～8 分钟。重点不是逐行念代码，而是说明同一输入、两种方案、对比结论和已知局限。

## 演示顺序

### 1. 项目介绍（约 40 秒）

讲解：

> 这是 FoodCoach 的单餐视觉评估切片 PlateLens。它对同一张餐盘图片同时运行传统视觉模型和多模态大模型，并排比较识别、定位、营养估算和反馈。项目明确区分事实和估算，不假装精确称重。

### 2. 输入与用户情境（约 30 秒）

- 上传学校餐盘照片
- 展示原图
- 设置体重、目标“减脂”、情境“练后”、餐盘直径
- 说明餐盘直径只用于面积换算

### 3. 传统方案（约 1 分钟）

- 点击“开始并排评估”
- 首次运行说明需要加载模型，所以较慢
- 展示左侧边界框和掩膜
- 说明流程：

```text
YOLO 检测 -> MobileSAM 分割 -> 面积估算 -> 营养表 -> 规则反馈
```

- 指出哪些食物被识别、哪些可能漏检
- 强调克数和热量是区间估算

### 4. 大模型方案（约 1 分钟）

- 展示右侧识别与反馈
- 说明图片、用户信息和情境一起进入 Qwen-VL
- 指出 JSON 会经过 Pydantic 校验
- 如果结果与左侧不同，不要掩饰，解释开放识别与数值幻觉的取舍

### 5. 并排对比（约 1 分钟）

逐项说明：

- 食物名称重合多少
- 热量差多少
- 谁提供 bbox / 掩膜
- 谁的反馈更自然
- 耗时和成本差异
- 哪种适合固定菜单，哪种适合开放菜品

### 6. 技术点（约 1 分钟）

展示代码或文档中的：

- `app/services/traditional.py`
- `app/services/vlm.py`
- `app/schemas.py`
- `data/nutrition.csv`
- `tests/`

说明：

- 两种方案统一到同一个 JSON
- 模型失败不会伪造结果
- 反馈包含“事实 → 解释 → 动作 → 长期提醒”
- 测试覆盖规则、分量、解析和 API

### 7. 局限与下一步（约 40 秒）

明确说出：

- YOLO-World 对中餐混合菜有限
- 单图无法精确称重
- 烹饪油和酱汁无法从营养表完全覆盖
- 后续会采集食堂图片并微调固定菜单检测器，保留大模型做未知菜品兜底
