# 运行视频脚本

## 录制前准备

1. 确认 `FoodCoach\.env` 已配置 API Key。
2. 执行 `.\scripts\run_all.ps1`。
3. 浏览器打开 `http://127.0.0.1:8501`。
4. 先分别试跑：
   - `餐07.jpg`：演示传统方案的白底四格盘效果。
   - `餐01.jpg`：演示学校混合菜下两种方案的差异。
5. 试跑完成后不要重启 API。再次使用相同图片和相同参数时会命中缓存，录制更流畅。

## 推荐时长

4～5 分钟。

## 录制顺序

### 1. 项目介绍（约 30 秒）

> 这是 FoodCoach 的单餐视觉评估切片 PlateLens。同一张餐盘图片会同时运行 YOLO + SAM 传统方案和 Qwen3.8-Omni-Flash 多模态方案，并排展示识别、营养估算和饮食建议。

### 2. 传统方案展示（约 1 分钟）

上传 `餐07.jpg`，设置：

- 目标：减脂
- 情境：练后
- 餐盘直径：26 cm

点击“开始并排评估”，展示：

- YOLO 边界框
- SAM 掩膜
- 食物列表和置信度
- 营养合计
- 规则生成的诚实反馈

说明：

> 白底分格盘的边界和食物区域比较清晰，传统方案可以给出可追溯的检测框、掩膜和营养计算。

### 3. 学校混合菜对比（约 1 分 30 秒）

上传 `餐01.jpg`，使用相同设置重新评估，展示：

- 传统方案识别到的食物及低置信度问题
- 大模型识别出的混合菜内容
- 两种方案在热量、名称和反馈上的差异
- 下方对比表中的结论

说明：

> 学校混合菜存在遮挡和混合烹饪，传统模型可能出现漏检或类别不稳定；大模型更适合开放菜品，但它的营养数值同样只是估算。

### 4. 技术与降级说明（约 40 秒）

展示：

- 统一 JSON 结构
- Pydantic 校验
- API 不可用时不会伪造结果
- 页面下载完整 JSON

### 5. 总结（约 30 秒）

说明：

- 传统方案适合标准摆盘、可解释定位和本地计算
- 大模型适合混合菜和自然语言解释
- 所有营养数据均为估算
- 项目不构成医疗或营养建议
