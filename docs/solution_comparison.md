# 两种方案对比

## 总览

| 维度 | 传统视觉方案 | 多模态大模型方案 |
|---|---|---|
| 核心模型 | YOLO-World + MobileSAM | Qwen3.8-Omni-Flash |
| 食物识别 | 20 类提示词内可定位；类别外漏检 | 能理解混合菜和开放类别，但可能名称漂移 |
| 定位 | bbox + 像素掩膜 | 仅可能有粗略 bbox |
| 分量 | 掩膜面积 + 厚度/密度假设 | 模型根据视觉比例直接估算 |
| 营养 | 本地营养表统一计算 | 模型直接输出，需范围校验 |
| 反馈 | 规则稳定、可复现 | 语言自然、情境理解更灵活 |
| 速度 | 本地 GPU 推理；首次加载慢 | 受网络、排队和供应商影响 |
| 成本 | 无单次 API 费用 | 按图片/模型/供应商计费 |
| 可解释性 | 高，可追溯到框、掩膜、营养表和公式 | 中低，主要依赖自然语言解释 |
| 失败模式 | 漏检、重复框、混合菜分割错误 | 幻觉食物、营养数值不稳定、JSON 格式错误 |

## 公平比较方式

1. 强制两张结果使用同一张原图。
2. 两种方案都接收相同的用户画像和本餐情境。
3. 统一转换到 `MethodResult` 后再比较。
4. 不把 VLM 的“自报置信度”当成真实概率。
5. 营养对比同时看总热量和三大营养素，不只比较名称。

## 结论

传统方案更适合：

- 固定食堂菜单
- 需要知道“在哪里”和“为什么这个数值”
- 批量处理、低边际成本
- 可复现的规则反馈

多模态大模型更适合：

- 菜品名称不固定
- 一道菜包含多种食材
- 需要自然语言解释和情境化沟通
- 图片背景复杂但不需要像素级定位

更合理的产品形态不是二选一，而是混合：

```text
传统模型负责识别、定位和营养表计算
大模型负责未知菜品兜底和自然语言反馈
规则层负责不可违反的事实、安全和措辞边界
```
