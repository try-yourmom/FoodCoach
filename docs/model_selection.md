# 大模型选择

## 最终候选

| 模型 | 定位 | 成本 | 本项目结论 |
|---|---|---|---|
| `qwen3.8-omni-flash` | 通用全模态的低成本 Flash 模型 | 低 | 默认候选，优先验证 |
| `qwen3-vl-plus` | 专用视觉语言 Plus 模型 | 较高 | 质量备选，Flash 不合格时切换 |
| `qwen3-vl-flash` | 专用视觉 Flash 模型 | 低 | 当前账号不存在该模型，不能使用 |
| `qwen-vl-max-latest` | 高能力视觉模型 | 高 | 本项目无必要 |

## 为什么先选 Omni Flash

PlateLens 每次只处理一张餐盘图片，输出字段固定，任务范围比通用视觉问答窄。对 10～20 张图片的课程演示来说，先使用 Flash 能明显降低试错成本。

Flash 的风险是：食物名称可能更粗、营养数值波动更大、复杂 JSON 偶尔不稳定。因此不能因为价格低就默认质量达标。

## 验收门槛

开通模型后，用 5 张固定图片比较 `qwen3.8-omni-flash` 与 `qwen3-vl-plus`：

1. JSON 首次解析成功率不低于 90%
2. 主要食物名称至少能识别出 3/5 张中的大部分菜品
3. 单次响应时间可接受
4. 营养估算没有明显数量级错误
5. 满足诚实反馈和免责声明要求

Flash 达标就保持默认；不达标再切换到 Plus。模型名称通过 `.env` 的 `VLM_MODEL` 配置，无需改代码。
